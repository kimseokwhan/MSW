27개 체크리스트의 확인 절차와 증빙 작성 방법은 [체크리스트 수행 가이드](checklist_guide.md)를 참고한다. 프로젝트를 처음 보는 평가자는 [상호 체크리스트 작성 가이드](peer_checklist_guide.md)에서 실행과 판정 순서를 확인할 수 있다.

검증일은 2026-11-19 KST다. 구현 범위는 F3001~F3019다. 여행 도메인은 사용자 확인 후 진행했다. 1일차 16시 이전 외부 API 검증 결과는 [API 검증 기록](api_verification.md)에 보존했다.

## 검증 재현

```bash
python -m backend.tools.registry
python -m unittest backend.tests.test_service backend.tests.test_external_apis backend.tests.test_llm -v
python -m pip check
```

## 대표 시나리오

[대표 시나리오 전체 응답과 실행 로그](evidence/scenario-runs.json)에 단계, Tool 호출, 재계획, 최종 응답을 담았다. 재계획의 발생 여부를 재현하기 위해 일부 시나리오에는 검증용 날씨와 관광지 데이터를 사용했다. 실연동 정상 응답은 [실제 Agent 실행 전체 로그](evidence/normal-live.json)에 기록했다.

### 11월 21일 경주 10~18시, 관광지 3곳

- **기대 동작과 관찰 결과** — 실제 응답은 경주 관광지 3곳과 날씨·시간 예산을 제공했다. 개별 운영시간과 이동시간은 확인이 필요하다고 표시했다.
- **로그와 차이** — GMS 의도 분석 → TourAPI 검색과 상세 5건 → Open-Meteo → 제약 판단 → 응답. 재계획 0회, 5.22초, 불일치 없음

### 경주 10~18시, 비가 오면 실내로

- **기대 동작과 관찰 결과** — 최대 강수 확률을 80%로 설정했다. 야외 후보를 제외하고 실내 유형 검색을 추가했다.
- **로그와 차이** — 유형 12 검색 → 상세 → 날씨 → 제약 판단 → 재계획 1회 → 유형 14 검색·상세. 날씨 호출 1회, 불일치 없음

### 경주 10~18시, 실내 시설 5곳

- **기대 동작과 관찰 결과** — 관광지 검색을 빈 결과로 설정했다. 대안 탐색 후 수량 미충족과 조건 조정 안내를 반환했다.
- **로그와 차이** — 최초 페이지와 새 페이지 3개의 합계 검색 4회. 재계획이 정확히 3회에서 종료, 불일치 없음

### 경주 10~18시, 비가 오면 실내로. 날씨 실패 조건

- **기대 동작과 관찰 결과** — 날씨를 `TIMEOUT`으로 설정했다. 관광지 초안을 제공하고 강수 조건 판단 불가와 오류 코드를 표시했다.
- **로그와 차이** — 관광지 검색·상세 성공, 날씨 실패, 부분 응답. 재계획 0회, 불일치 없음

### 안녕하세요

- **기대 동작과 관찰 결과** — 여행 조건의 입력을 안내했다.
- **로그와 차이** — 요청 분석 → 최종 응답, 외부 Tool 및 모델 호출 0회, 불일치 없음

### 경주 여행 일정 짜 줘 → 날짜·시간·수량 보완 → 종료만 변경

- **기대 동작과 관찰 결과** — 필수 입력이 없을 때 질문했다. 세션 후속 요청에서 지역과 시작 시간은 유지되고 종료 시간만 변경됐다.
- **로그와 차이** — 첫 턴 Tool 호출 0회. 후속 두 턴의 변경 범위 검증 통과

- **F3001~F3004** — 등록된 외부 Tool 4개의 입력 스키마, 실제 관광지 ID 전달과 상세 응답, 현재 카탈로그 기준, 실제 TourAPI 빈 검색의 `NO_RESULT`, 실제 에어코리아 결측 및 날씨 결측·예보 범위 처리. [API 기록](api_verification.md)
- **F3005~F3011** — LangGraph 노드와 실행 분기, 조건 추출, 동일 세션 후속 변경, 480분 예산, 강수 재계획, 데이터 재사용 및 3회 상한, 후보 근거 및 제외 사유. [Agent 설계](agent_design.md) · [실제 전체 로그](evidence/normal-live.json) · [대표 실행](evidence/scenario-runs.json)
- **F3012~F3014** — 단계 진입·종료, Tool 입력과 정제한 결과·시간, LLM 판단 근거 저장. 구독자 누락·실패 시 대화 지속, 세션 구분, 목록·상세·삭제와 수정 API 부재. [실행 로그 화면](evidence/logs.png)
- **F3015~F3016** — 일정 저장·목록·상세·수정·삭제. 겹치는 계획 저장과 충돌 반환, 시간대 경계의 비충돌 확인. 브라우저에서 저장, 상세, 제목 수정 후 목록 갱신 확인. 삭제는 격리된 SQLite의 실제 API에서 확인. [계획 관리 화면](evidence/plans.png)
