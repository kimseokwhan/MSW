Git을 통한 버전관리 규칙
0. 초기 커밋은 기본적인 폴더와 .gitignore를 포함한다.
1. 메인 브랜치에는 작업 후 작동을 확인한 결과물만 푸쉬한다.
2. 각자 로컬에서 브랜치를 생성하여 작업하고, 작업이 끝났다고 생각하면 메인 브랜치에 푸쉬한다.
3. 브랜치 머지 중, 다른 팀원의 작업물과 겹치는 상황이 온다면 리퀘스트를 요청하여 양쪽 전부가 확인한다.
4. 각 기능 구현 단위로 커밋하며, 커밋 메시지에는 간결하게 작업 내용을 작성한다.
5. README.md 작성이나 주석 수정같은 작동에 관련없는 단일 파일 수정은 로컬에서 확인 후 곧장 메인으로 푸쉬한다.

##느낀 점

박은하 : 프로젝트를 계속 진행하면서 느낀 점은, 이렇게 명세서처럼 요구사항이 명확할 수록 구현하기 쉽다는 것이다. 다른 개인 프로젝트의 경우 새로 기능을 만들면 이전 기능과 충돌하는 경우가 생겨서 꼬이는 점이 많았다. 그런데 이렇게 요구사항이 단계별로 명확하게 주어지니까 커밋 단위로 확실히 할 수 있고, 기존 기능에 추가만 하면 되니 버전관리가 꼬일 일도 없었다. 이러한 점이 왜 명세서를 구체적으로 만들어야 하는가? 를 고찰하는 계기가 되었다.
