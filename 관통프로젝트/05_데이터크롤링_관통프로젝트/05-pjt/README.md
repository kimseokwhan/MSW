<프로젝트 개요>

프로젝트명: 주식 커뮤니티 댓글 분석 시스템

분석 대상 기업: 삼성바이오로직스

개발 환경: Python, Django, Selenium, SQLite, GMS LLM API

프로젝트 목표: 사용자가 입력한 기업의 토스증권 커뮤니티 댓글을 실시간으로 수집하고, 전처리 및 AI 텍스트 증강 결과를 데이터베이스에 저장하여 웹 화면에 통합 출력하는 서비스 구현



1. 안재현

담당 역할: 웹 프론트엔드 및 프로젝트 기반 구축

F601. 회사명 입력 및 검증

Django의 View와 HTML Template을 활용하여 회사명 입력 화면 구현

POST 방식으로 사용자가 입력한 회사명을 서버에 전달

입력한 회사명이 VS Code 터미널에 출력되도록 구성

F602. 데이터베이스 스키마 구성

Django ORM을 활용하여 CommentAnalysis 모델 설계

실제 종목명, 종목코드, 원본 댓글, 정제 댓글, 증강 댓글, IQR 임계값 및 생성 일시를 저장할 수 있도록 필드 구성

여러 개의 댓글을 리스트 형태로 관리하기 위해 JSONField 활용

makemigrations, migrate 명령어를 통한 데이터베이스 생성 및 관리

F603. 회사 검색 및 종목 선택

Selenium을 활용한 토스증권 회사 검색 기능 구성

사용자 입력값을 기반으로 검색 결과에서 해당 종목을 선택하는 기능 연계

삼성바이오로직스를 분석 대상 기업으로 설정하여 검색 과정 테스트

검색된 종목 정보를 이후 댓글 수집 단계에서 활용할 수 있도록 구성

F607. 데이터 통합 및 결과 출력

팀원이 구현한 댓글 수집·전처리·증강 기능을 Django와 연동

run_pipeline.py의 처리 결과를 Django View에서 활용하도록 연결

원본 댓글, 정제 댓글, 증강 댓글을 하나의 분석 결과로 통합

통합 데이터를 CommentAnalysis 모델을 통해 DB에 저장하도록 구현

HTML과 CSS를 활용하여 단계별 댓글 목록과 개수를 구분하여 출력

회사명 미입력, 댓글 미수집 등 예외 상황에 대한 안내 기능 추가

Django 웹 애플리케이션 구조

Django의 MTV 패턴에서 Model, View, Template이 각각 담당하는 역할을 이해하였다.

urls.py, views.py, index.html을 연결하여 입력부터 결과 출력까지의 흐름을 구현하였다.

데이터베이스 설계 및 관리

JSONField를 통해 여러 댓글 데이터를 하나의 분석 결과로 관리하는 방법을 익혔다.

마이그레이션의 역할과 데이터베이스 구조를 변경할 때 주의해야 할 점을 이해하였다.

Selenium 및 데이터 처리 파이프라인 연계

Selenium을 활용한 동적 웹 페이지 검색과 종목 선택 과정을 학습하였다.

크롤링, 전처리, LLM 증강으로 이어지는 데이터 처리 흐름을 이해하였다.

팀원이 작성한 Python 모듈을 Django에서 불러와 활용하면서 함수의 입력값과 반환값을 일치시키는 것이 중요하다는 점을 배웠다.

GitLab 협업 및 오류 해결

기능별 브랜치를 활용하여 팀원과 독립적으로 작업하는 방법을 익혔다.

Git Pull, Commit, Push, Merge 과정을 통해 작업물을 통합하는 경험을 쌓았다.

코드 병합 이후 발생할 수 있는 import 경로 문제와 프로젝트 파일 구조의 차이를 확인하고 수정하는 과정을 학습하였다.

.gitignore 설정과 가상환경, 환경변수 파일 관리의 중요성을 이해하였다.

* 어려웠던 점 및 해결 과정

① 팀원 간 프로젝트 파일 구조 차이

초기에는 데이터 처리 모듈이 Django 앱 내부에 위치할 것으로 예상했지만, 실제로는 프로젝트 최상위 폴더에 구성되어 있어 연동 과정에서 어려움이 있었다.

기존 파일 구조를 확인한 뒤 불필요한 파일 이동이나 중복 구현을 피하고, import 경로를 수정하여 기존 파이프라인을 재사용하는 방향으로 해결하였다.

② 개별 기능의 통합

회사명 입력, 데이터 수집, 전처리, 증강 기능이 각각 구현되어 있어 이를 하나의 실행 흐름으로 연결하는 과정이 어려웠다.

각 함수의 반환 데이터 구조를 확인하고 Django View에서 파이프라인을 호출하도록 구성하여 데이터 처리 결과를 DB 저장 및 웹 화면 출력으로 연결하였다.

③ GitLab 협업 및 환경 설정

브랜치 병합 과정에서 파일 충돌과 .gitignore 설정 문제를 경험하였다. 또한 팀원 간 가상환경과 API 환경변수 설정이 달라 실행 오류가 발생할 수 있음을 확인하였다.

Git 상태와 변경 파일을 확인하고, 공통 프로젝트 구조를 유지하면서 환경 설정을 점검하는 방식으로 문제를 해결하고자 하였다.

* 느낀 점

이번 프로젝트에서는 웹 화면 구현뿐만 아니라 Django 프로젝트의 기본 구조 설계, 데이터베이스 구성, 팀원 코드 통합까지 담당하면서 전체적인 웹 서비스 개발 흐름을 이해할 수 있었다.

특히 가장 인상 깊었던 부분은 각각 정상적으로 동작하는 코드라도 하나의 프로젝트로 합치는 과정에서 새로운 문제가 발생할 수 있다는 점이었다. 단순히 기능을 구현하는 것뿐만 아니라 파일 구조, import 경로, 함수의 반환값, 데이터 저장 방식 등을 일관되게 관리하는 것이 중요하다는 사실을 배웠다.

또한 GitLab을 활용한 협업 과정에서 다른 팀원의 작업 내용을 이해하고 기존 코드를 최대한 유지하면서 기능을 연결하는 경험을 할 수 있었다.

앞으로는 프로젝트 초기 단계에서 팀원 간 함수의 입출력 형식과 파일 구조를 더 구체적으로 협의하고, 기능별 테스트를 진행하여 통합 과정에서 발생하는 오류를 줄이고 싶다.

## 학습 내용

- **동적 페이지 크롤링**: 자바스크립트로 그려지는 화면은 요소가 나타날 때까지 `WebDriverWait`로 기다려야 한다는 것을 배웠습니다. 또 클래스 이름은 배포마다 바뀔 수 있어서, 역할을 나타내는 속성을 기준으로 선택자를 잡는 방식을 익혔습니다.
- **내부 스크롤 처리**: 댓글 목록은 페이지 전체가 아니라 별도의 스크롤 상자에서 스크롤되어서, 그 요소를 찾아 `End` 키를 보내는 방식으로 수집했습니다.
- **정규표현식과 pandas**: 정규식으로 특수문자와 공백을 정리하고, DataFrame으로 조건 필터링을 하는 흐름을 학습했습니다.
- **IQR 이상치 제거**: 길이 분포의 Q1, Q3로 정상 범위를 계산해 이상치를 걸러내는 방법을 적용해 봤습니다. 댓글이 너무 적을 때는 통계가 의미 없어서 별도 기준을 두는 이유도 이해했습니다.
- **프롬프트 설계와 응답 검증**: LLM 응답은 형식이 어긋날 수 있어서, JSON 배열만 요청하고 파싱 실패나 개수 불일치를 코드로 검증해야 한다는 점을 배웠습니다.
- **모듈화와 import**: 파일을 역할별로 나누고 `if __name__ == '__main__'`로 직접 실행과 import를 구분하는 이유를 이해했습니다. Django 앱 안에서는 상대 import(`from .llm import ...`)를 써야 했습니다.

## 느낀 점

- 제공받은 코드가 이미 잘 나뉘어 있었지만, 실제 프로젝트에 넣으려니 경로, import, 반환 형식 같은 부분을 맞추는 일이 생각보다 많았습니다. 코드를 그대로 쓰는 것과 내 프로젝트에 연결하는 것은 다르다는 것을 느꼈습니다.
- 크롤링은 사이트 구조가 바뀌면 바로 깨질 수 있어서, 예외 처리와 대기 시간 설정이 중요하다는 것을 알게 됐습니다.
- LLM은 지시한 형식대로 항상 답하지 않기 때문에, 결과를 믿고 쓰기보다 검증하는 코드가 꼭 필요하다고 느꼈습니다.
