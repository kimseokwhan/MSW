# 06-pjt 도서 커뮤니티 프로젝트

## 프로젝트 개요

Django를 활용하여 도서 정보를 관리하고, 사용자가 도서에 대한 감상을 쓰레드로 작성하고 공유할 수 있는 도서 커뮤니티 웹 애플리케이션을 구현하였다.

도서와 쓰레드의 생성, 조회, 수정, 삭제 기능을 구현하고, 사용자 인증과 작성자 권한 검사를 적용하였다. 또한 사용자 간 팔로우, 쓰레드 좋아요 및 댓글 기능을 통해 감상을 공유할 수 있도록 하였으며, 카테고리별 도서 검색과 선호 카테고리 설정 기능을 추가하여 사용자의 도서 탐색을 지원하였다.

## 김석환

### 1. 주요 기능

- **User Model (F602)**: AbstractUser를 상속받아 커스텀 사용자 모델을 구현하고 팔로우를 위한 M:N 관계 설정

- **Form (F603)**: Django Form을 활용한 회원가입 및 회원정보 입력 데이터 검증

- **login (F607)**: 사용자 인증 및 로그인 세션 생성

- **logout (F608)**: 로그인 세션 종료

- **signup (F609)**: 신규 회원가입 및 가입 후 자동 로그인

- **profile (F610)**: 사용자 정보, 작성한 쓰레드, 팔로워 및 팔로잉 정보 조회

- **follow (F611)**: 사용자 간 팔로우 및 언팔로우 기능 구현

- **update (F612)**: 로그인한 사용자의 회원정보 수정

- **delete (F613)**: 사용자 계정 삭제 및 회원탈퇴

- **change_password (F614)**: 비밀번호 변경 및 로그인 상태 유지

- **카테고리 (F628)**: 사용자와 카테고리의 M:N 관계를 활용한 선호 카테고리 선택 및 프로필 조회 기능 구현

- **Git 활용 (NF601)**: Git을 활용하여 팀원 간 역할을 분담하고, 변경 사항을 커밋하여 프로젝트를 관리

- **URL 구성 (NF602)**: URL 이름을 활용하여 페이지 간 연결 및 유지보수가 용이하도록 구현

- **HTTP Method 제한 (NF603)**: 데코레이터를 활용하여 각 View에서 허용된 HTTP 요청 방식만 처리

### 2. 학습 내용

- AbstractUser를 상속받아 커스텀 사용자 모델을 구현하고 사용자 정보를 관리하는 방법 학습

- UserCreationForm, UserChangeForm, AuthenticationForm, PasswordChangeForm을 활용한 사용자 입력값 검증 방법 학습

- Django Authentication System을 활용한 사용자 인증 및 로그인 세션 관리 방법 학습

- ManyToManyField를 활용하여 사용자 간 팔로우 관계를 설정하고 추가 및 삭제하는 방법 학습

- 역참조를 활용하여 프로필 페이지에서 작성한 쓰레드와 팔로워 및 팔로잉 정보를 조회하는 방법 학습

- login_required와 사용자 비교를 활용하여 인증 여부 및 접근 권한을 제한하는 방법 학습

- update_session_auth_hash를 활용하여 비밀번호 변경 후 로그인 상태를 유지하는 방법 학습

- URL 이름을 활용한 페이지 연결과 HTTP Method 제한 데코레이터의 사용 방법 학습

### 3. 느낀 점

accounts 앱을 구현하면서 Django의 인증 시스템을 활용해 회원가입, 로그인, 로그아웃, 회원정보 수정 및 탈퇴 기능을 구현할 수 있었다.

또한 팔로우 기능을 통해 사용자 간의 관계를 관리하고, 프로필 페이지에서 작성한 게시글을 조회하는 기능도 구현했다.

개발 과정에서 `login_required`와 HTTP 요청 제한 데코레이터 등을 활용하며 사용자 인증과 접근 권한 관리의 중요성을 배울 수 있었다. 특히 Django에서 제공하는 Form과 인증 관련 기능을 활용하면 복잡한 기능도 효율적으로 구현할 수 있다는 점을 느꼈다.

## 박채욱

### 1. 주요 기능

- **Book Model (F604)**: 도서 정보를 저장하고 사용자 및 카테고리와의 관계 설정

- **Thread Model (F605)**: 도서별 쓰레드 데이터를 저장하고 작성자, 도서, 좋아요 관계 설정

- **Form (F606)**: ModelForm을 활용한 도서 및 쓰레드 입력 데이터 검증

- **index (F615)**: 전체 도서 목록 조회 및 카테고리별 필터링

- **create (F616)**: 로그인한 사용자의 도서 정보 등록

- **detail (F617)**: 선택한 도서의 상세 정보와 관련 쓰레드 목록 조회

- **update (F618)**: 작성자만 기존 도서 정보를 수정할 수 있도록 구현

- **delete (F619)**: 작성자만 도서 데이터를 삭제할 수 있도록 구현

- **thread_create (F620)**: 선택한 도서에 대한 쓰레드 작성 및 저장

- **thread_detail (F621)**: 쓰레드 상세 정보와 좋아요 및 댓글 조회

- **thread_update (F622)**: 작성자만 쓰레드 내용을 수정할 수 있도록 구현

- **thread_delete (F623)**: 작성자만 쓰레드를 삭제할 수 있도록 구현

- **like (F624)**: 사용자와 쓰레드의 M:N 관계를 활용한 좋아요 및 취소 기능

- **댓글 (F627)**: 쓰레드 댓글 작성, 조회 및 작성자별 삭제 기능 구현

- **카테고리 (F628)**: 카테고리 모델을 활용한 도서 장르 분류 및 필터링 기능 구현

### 2. 학습 내용

- ForeignKey를 활용한 User, Book, Thread 간의 N:1 관계 설정 및 데이터 연결 방법 학습

- ManyToManyField를 활용한 사용자와 쓰레드 간 좋아요 관계 구현 방법 학습

- ModelForm을 활용한 사용자 입력값 검증과 데이터 저장 방법 학습

- `commit=False`를 활용하여 작성자 및 도서 정보를 연결한 후 데이터를 저장하는 방법 학습

- `login_required`와 작성자 비교를 활용하여 데이터 생성, 수정, 삭제 권한을 제한하는 방법 학습

- `select_related`를 활용하여 관계된 모델의 데이터를 함께 조회하는 방법 학습

- `filter`, `exists`, `add`, `remove`를 활용한 좋아요 및 관계 데이터 처리 방법 학습

- 카테고리와 도서 간 관계를 설정하고 QuerySet 필터링을 통해 조건에 맞는 데이터를 조회하는 방법 학습

- `require_safe`, `require_POST`, `require_http_methods`를 활용한 HTTP 요청 방식 제한 방법 학습

### 3. 느낀 점

이번 프로젝트에서는 도서와 쓰레드의 CRUD 기능을 구현하고, 여러 모델 간의 관계를 연결하는 과정을 학습할 수 있었습니다. 이전 프로젝트에서는 개별 모델을 중심으로 데이터를 처리했지만, 이번에는 도서와 쓰레드, 사용자 사이의 관계를 고려해야 했기 때문에 데이터가 어떤 방식으로 연결되고 저장되는지 이해하는 것이 중요했습니다.

특히 쓰레드를 작성할 때 `commit=False`를 사용하여 작성자와 도서 정보를 연결하고, 수정과 삭제 기능에서는 로그인한 사용자와 실제 작성자를 비교하여 권한을 제한하는 과정을 익힐 수 있었습니다. 또한 좋아요 기능을 구현하면서 M:N 관계의 데이터를 추가하거나 제거하는 방법을 학습하였고, 댓글과 카테고리 기능을 추가하며 기존 모델과 View를 확장하는 경험을 할 수 있었습니다.

여러 기능을 구현하는 과정에서 개별 코드뿐 아니라 Model, Form, View, Template 사이의 데이터 흐름을 함께 확인해야 한다는 점을 느꼈습니다. 기능이 늘어날수록 각 요소의 연결 관계를 정확히 파악하고, 실제 실행 화면에서 데이터가 의도한 대로 처리되는지 확인하는 과정이 중요하다는 것을 배웠습니다.
